# foc-observer indexer

A Ponder app that indexes FOC contract events on Filecoin mainnet or calibnet into Postgres. One codebase serves both networks: `PONDER_NETWORK` selects one, and Compose runs an instance per network, each with its own database. Read the root `AGENTS.md` first; this file covers what is specific to the indexer.

## Ponder on Filecoin

The indexer runs on [filecoin-ponder](https://github.com/FilOzone/filecoin-ponder), a Ponder fork installed from npm under the name `ponder` (see `package.json`). Upstream Ponder doesn't support Filecoin. The fork:

- skips null rounds, epochs that have no block (Lotus answers `eth_getBlockByNumber` for one with RPC error code 12)
- skips Ponder's logs-bloom consistency check, because the FVM sets every bloom bit
- synthesises a placeholder start block when a Lotus gateway's lookback limit can't serve it
- treats Filecoin as having 900-block finality

A fix in the fork reaches the indexer only through a new npm release, a dependency bump here, and an image rebuild. The fork's repository documents its internals.

## Layout

- `ponder.config.ts`: the only Ponder config. It reads network constants from `src/networks.ts`, and `DATABASE_URL` and `RPC_URL` from the environment (required when `PONDER_STRICT_ENV=true`, as in Compose).
- `src/networks.ts`: per-network chain ID, start blocks, upgrade blocks and contract addresses.
- `ponder.schema.ts`: Ponder table exports generated from `src/schema-defs.ts`. Don't define tables here.
- `src/schema-defs.ts`: every table's columns, types, indexes and descriptions, defined once. The server copies it for its table allow-list and agent context.
- Handlers, one file per contract: `pdp-verifier.ts`, `fwss.ts`, `storacha-fwss.ts`, `filecoin-pay.ts`, `filecoin-pay-burns.ts` (`burnForFees` emits no event, so it's read from transaction data), `filbeam.ts`, `sp-registry.ts`, `session-keys.ts`, `porep.ts`.
- `src/event-utils.ts`: `eventId`, `txEventId` and `eventMeta`. `src/tx-meta.ts`: `recordTx`. `src/cid-utils.ts`: PieceCID decoding to a CID string and raw size.
- `src/api/index.ts`: an empty Hono app; Ponder requires one. The server reads Postgres directly and doesn't call the indexer.
- `abis/`: TypeScript ABI exports generated by `scripts/generate-abis.sh`, plus `fwss-extra-events.json`.
- `test/`: `node --test` suites. `handler-parity.test.ts` checks that every handler calls `recordTx` first, and `schema-exports.test.ts` that `ponder.schema.ts` and `schema-defs.ts` agree.

## Handlers

```typescript
ponder.on("PDPVerifier:DataSetDeleted", async ({ event, context }) => {
  await recordTx(event, context)
  const { setId, deletedLeafCount } = event.args
  await context.db
    .insert(pdpDataSetDeleted)
    .values({ id: eventId(event), setId, deletedLeafCount, ...eventMeta(event) })
})
```

- `recordTx` comes first in every handler. It writes the transaction's `tx_meta` row, which event rows join to; a handler without it writes rows with nothing to join to, and no query fails. `handler-parity.test.ts` enforces this.
- `eventId(event)` is the block hash plus log index. `txEventId` is the block hash plus transaction index, for handlers that have no log. `eventMeta(event)` supplies `tx_hash`, `block_number` and `timestamp`. Transaction fields belong in `tx_meta`, never on event rows.
- Keep `includeTransactionReceipts: true` in `ponder.config.ts`. It's what gives handlers `event.transactionReceipt`, which `recordTx` needs for gas and status.
- Destructure `event.args` at the top. Store arrays and objects with `JSON.stringify`, decode PieceCIDs with `decodePiece`, and decode SP capability bytes to UTF-8 with a hex fallback, as `sp-registry.ts` does.
- The Storacha handlers mirror `fwss.ts` for its FWSS fork, which stays on v1.2.x semantics. Where the union ABI types an argument by newer semantics (`approver` on `ServiceTerminated`), the Storacha handler writes it to the column its version means (`caller`); the bytes on the wire are identical.

### Adding an event or a contract

1. Get the ABI into `abis/`, by `./scripts/generate-abis.sh [ref]` for filecoin-services contracts or by hand for the rest.
2. Define the table in `src/schema-defs.ts` and export it from `ponder.schema.ts`.
3. For a new contract, add its addresses and start block to both networks in `src/networks.ts`, and its entry to `ponder.config.ts`.
4. Write the handler in the contract's `src/*.ts` file.
5. Plan a [reindex](../REINDEX.md) when the build ID changes. A newly handled event also needs RPC from its start block, so start its entry at the block the contract began emitting it, as the `*_V*_BLOCK` constants do.

## ABIs

`scripts/generate-abis.sh` fetches published ABIs from [filecoin-services](https://github.com/FilOzone/filecoin-services) at a pinned ref (or the one passed). The FWSS ABI it writes is a union:

- events from `abi/Rails.abi.json`, which FWSS's `Rails` library declares and the FWSS proxy emits, but `forge inspect` leaves out of the contract ABI
- `fwss-extra-events.json`, hand-maintained legacy entries such as `PricingUpdated`, which current source no longer declares but older deployments emit and reindexes backfill

Subscribing to an event a deployment never emits is harmless, so one ABI serves every deployed version.

## Data correctness

- Settlement amounts are incremental per event, despite the "total" in some names; sum them across events. `settled_up_to` is the only cumulative field.
- Piece CIDs are stored as strings. For a PieceCIDv2 example and its decoded `raw_size`, see the `bafkzcibcp4b...` vector in [`test/cid-utils.test.ts`](test/cid-utils.test.ts). `leaf_count` measures FR32-expanded data, not raw bytes.
- `status` in `tx_meta` is always `0x1`: Ponder doesn't dispatch events from reverted transactions.

## Build and test

```sh
npm ci
npm test                       # node --test test/*.test.ts
npm run codegen:calibnet       # writes ponder-env.d.ts
npm run typecheck              # codegen:mainnet, then tsc --noEmit
npm run dev:calibnet           # local development against a calibnet RPC and Postgres
```

`npm run dev` doesn't checkpoint and starts from scratch each time; `npm start` resumes from Postgres.
